What determines a passing score?

The task sets requirements, execution produces evidence, and graders apply criteria. The score is the result of that chain.

The parts of one run

A repair task provides a request, buggy code, and visible feedback. The environment provides files and tools. The agent works within a budget, leaving candidate code, tool records, and a final message. These are the grading materials. Criteria define success in advance; graders apply them to the materials.

A grader is a mechanism that turns evidence into a judgment or score using defined criteria. It may be a test program, a model applying a rubric, or a human reviewer. A single repair can have multiple graders for functionality, allowed changes, verification claims, and maintainability. An aggregation rule determines how those findings support a decision.

The evaluation harness prepares the environment, starts each trial, collects evidence, invokes graders, and saves results. The agent decides how to do the task; the harness makes attempts executable and comparable under specified conditions.

From one run to an evaluation set

A pass describes one artifact. Comparing prompts requires the same starting point. Observing generation variability requires repeating from that point. Understanding coverage requires other kinds of tasks. This project therefore extends individual trials into repeats and an A/B comparison, retaining identities at every level.

LevelAdditional observationQuestion it supports
One trialArtifact and traceHow did this attempt perform?

Each record identifies at least a task, version, and repeat. A score change can then be traced back to a particular task and run.

These components explain where a score comes from. The next choice is which findings to retain separately.
