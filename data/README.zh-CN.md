# 任务集构建记录

当前任务集是 QuixBugs 的 8 题实验适配，固定上游提交 `4257f44b0ff1181dedaedee6a447e133219fcebf`，MIT 许可。它是真实程序修复基准的子集，不是工业仓库 issue，也不代表 QuixBugs 官方得分。

## 选择与改编

- dev：knapsack、lcs_length、shunting_yard；holdout：next_permutation、kheapsort、lis、mergesort、find_first_in_sorted。
- 选择条件：单文件、标准库、短时间可执行、明确输入契约、覆盖边界/状态/顺序/终止问题。没有按 A/B 胜负选题，难度由后续实测检验。
- 上游原始缺陷代码和参考代码不改动，存入 `quixbugs/buggy`、`quixbugs/correct`。只在生成任务时追加 JSON 输入的 `solve(value)` 适配器，生成器转列表。
- 输入规模有明确上限。采用独立枚举/暴力 oracle 生成预期，避免把上游参考实现直接当唯一真相；每题参考修复必须通过全部验收。
- `build_tasks.py` 固定生成公开样例及互不重合的验收用例。`target` 与 `regression` 是交错划分的两组合同检查，不是逐例证明过的“必失败/必通过”标签。真实缺陷可能同时破坏两组；不要求损坏版本通过所有 regression。
- 上游源文件里的公开示例保留可见。所谓独立验收，是这些用例和预期不经工具接口提供给 agent；候选 Python 运行器不是对抗性隔离沙箱。
- 没有纳入官方超大慢用例；本项目不测大规模性能、跨文件定位、仓库环境修复、架构质量。

## 质量关卡

`python data/build_tasks.py` 可重建 `tasks.json`、`tests/oracles.json`、`data/provenance.json`。后者保存路径、版本和源文件 SHA-256。

离线测试检查：缺陷版本验收失败、参考版本通过公开及独立用例、每题一个貌似合理的错误修复被拒绝、来源哈希与 3/5 划分正确。用暴力方法求每个预期，不表示穷尽题目声明的输入域：例如 lis 声明至多 8 个元素，生成器只枚举了至多 5 个元素的排列。这些验收不能证明完整算法正确。

`wrap` 在入选前被排除：参考实现对某些带前导空格的输入可能无法推进循环（`end == 0`）。原始下载文件仅保留作排除记录，不进入任务集。这个判断来自代码检查，未将其包装为 agent 实测失败。

## 复用与泄漏

所有任务、验收与参考修复在开源仓库中公开，模型也可能在训练中见过 QuixBugs。holdout 表示本次 prompt 开发不使用的部分，不表示对模型训练未知。报告须保留这一限制。若根据此次结果改 prompt，下次必须用新版本的评测集确认。
