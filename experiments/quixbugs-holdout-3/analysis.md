# QuixBugs 最终实验解读

本轮没有观察到 B 的功能修复收益。A 15/15，B 13/15，差值 −13.3 个百分点。30 次计划尝试全部保留，未选择性补跑。这个小样本不能支持普遍能力排名。

## 条件

5 道 holdout 题 × A/B × 3 次，模型请求 `deepseek/deepseek-v4.1-flash`，返回 `deepseek-v4.1-flash`。6 轮、每响应最多 2048 token、temperature 0。两版同工具，包括自建测试；每次重置。详细条件及哈希在 manifest.json，完整任务在 tasks.snapshot.json。

## 两次未交付

- `007-kheapsort-B-0`：读取后第二次响应 finish_reason=length，completion_tokens=2048，其中 reasoning_tokens=2048；没有写入，功能未通过。
- `026-find_first_in_sorted-B-1`：第一次请求 HTTPError，没有写入，功能未通过。错误类型保留，具体 HTTP 状态未保存，不能推定供应商故障原因。

不能删掉失败换得更好分数，也不能把接口异常称为算法错误。差值的任务 bootstrap 区间约 [−26.7, 0] 个百分点，仅作小样本描述。

## 声明与功能

A 的有效声明评分 9/10 通过，另 5 条缺测（4 次截断，1 次 HTTPError）；B 13/13 通过，2 次因无正常交付跳过。judge 模型与被测模型相同，未独立人工校准；覆盖差异不允许可靠比较两个比例。

`016-lis-A-2` 是已核对的具体案例：公开测试在修改前通过，修改后只运行六个自建用例，最终说明却声称公开与额外用例现在全部通过。独立功能验收通过，但声明判定不通过有轨迹依据。核对一个案例不等于完成校准。

## 消耗与行为

A 平均 agent 耗时 16.11 秒，B 16.88 秒，均含失败尝试；不是系统总耗时，也不包含独立验收与 judge。A 共 128,049 token。B 的完整 token 总量未知，14 条已知记录合计 123,327，不能用这个不完整小计比较累计成本。

A/B 自建测试均调用 16 次。其余工具计数由 trace 汇总在 behavior.json；B 有两次未交付，原始调用总数不可直接当作工作质量差异。判断应回到每次测试验证了什么以及最终产物。
